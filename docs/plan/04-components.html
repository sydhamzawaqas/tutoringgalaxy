1. Approach and rules

One component system for the whole product (marketing site, logged-in app and admin), so a parent moving from the homepage to a progress report sees one brand.

Approach

  • shadcn/ui is the base for about 90% of the UI. Its components are copied into src/components/ui, so we own the code. They're built on Radix (or Base UI) primitives, which handle keyboard, focus and ARIA for us, and they're themed from one set of CSS variables. This fixes the "29 hex colors, 18 color families, 8 radius styles" problem from the audit.
  • Aceternity UI only adds accents: at most one ambient effect on the homepage hero, plus optional story pieces (About timeline, testimonials, curricula bento). Aceternity is distributed through the same shadcn CLI (@aceternity/…), so the files land in the same folder and use the same tokens.
  • Magic UI is optional (MIT): we may use one or two utilities, such as a CSS-only marquee or a one-time blur-fade. It isn't required.
  • Plain npm libraries for specialist jobs: KaTeX for maths, react-hook-form + zod for forms, TanStack Table for admin, Recharts (via shadcn Chart) for progress.
  • One icon family: Lucide, which shadcn uses by default. No emoji icons. Aceternity pieces that import @tabler/icons-react get their icons swapped to Lucide when we add them.

Rules every component has to follow

  1. No more than 1–2 motion effects per page. Motion the visitor didn't trigger appears only in the homepage hero. Everything else animates only in response to an action, like opening, expanding or confirming.
  2. Respect prefers-reduced-motion. Every Motion/Aceternity piece checks useReducedMotion() or uses Tailwind motion-reduce: and falls back to a static state. Content must never depend on an animation to appear.
  3. Keyboard-accessible, with a visible focus ring. Every interactive component works with Tab, Enter, Space, Esc and the arrow keys. Touch targets are at least 44×44px. Decorative layers get aria-hidden and pointer-events:none.
  4. One primary CTA label: "Book a free trial". Plus one WhatsApp action. No new button styles (moving borders, shimmer, rainbow).
  5. Content lives at URLs, not in modals. Tutor profiles, practice questions and reports each get their own page. Dialogs are only for confirmations and short tasks.
  6. Only real data. Testimonial, tutor and stat components ship empty, or get hidden, until the client supplies real, permissioned content.
  7. Client components stay small. Effects are loaded as leaf client components, so marketing pages remain mostly server-rendered.

3. Avoid list

These components exist in the libraries (we checked the names), and many look impressive in a demo. Each one would bring back a problem the audit found: the generic AI look, too much motion, too many CTAs, crowded mobile screens, or content that's hard to reach.

  • 3D globes: GitHub Globe (Aceternity), Globe (Magic UI)

    Adds three.js/WebGL or cobe weight to the page that matters most for LCP and INP on mid-range Android phones. A list of 11 countries is easier to read than a spinning planet.

    Instead: a plain list of countries, or Magic UI Dotted Map (static SVG) on About if the owner insists.
  • Particle and ambient backgrounds: Sparkles, Meteors, Vortex, Aurora Background, Wavy Background, Background Beams, Particles, Warp Background

    This is exactly the "galaxy / purple-gradient" AI look the audit flagged. Continuous canvas animation drains batteries and competes with the content.

    Instead: one Spotlight New in the hero, or a static grid.
  • Glass and hover-gimmick cards: Card Spotlight, Glare Card, 3D Card Effect, Wobble Card, 3D Pin, Direction Aware Hover, Magic Card, Neon Gradient Card

    Brings back the old "glass badges". Hover effects don't exist on touch screens, where most parents browse.

    Instead: shadcn Card with a border, one subtle shadow, and a focus ring.
  • Auto-playing carousels: Infinite Moving Cards, Images Slider, autoplay on Apple Cards Carousel or Animated Testimonials

    Content that moves on its own fails WCAG 2.2.2 (Pause, Stop, Hide) unless it has controls, and visitors miss most of the slides.

    Instead: static testimonial cards, or a carousel the visitor controls.
  • Animated headline text: Typewriter Effect, Flip Words, Text Generate Effect, Encrypted Text, Colourful Text, Hero Highlight, Hyper Text, Sparkles Text, Morphing Text, Aurora Text, Animated Gradient Text

    Screen readers may read partial or garbled words, and highlighting one word in the headline is a well-known sign of generated design.

    Instead: a well-set static headline in the brand typeface.
  • Animated CTA buttons: Moving Border, Hover Border Gradient, Shimmer Button, Rainbow Button, Pulsating Button, Border Beam, Shine Border

    The audit counted 14 CTA variants. Every animated button style adds another kind of CTA and competes with "Book a free trial".

    Instead: one Button set (primary, secondary, ghost, plus a WhatsApp variant).
  • Scroll-jacking: MacBook Scroll, Hero Parallax, Container Scroll Animation, Sticky Scroll Reveal, Parallax Scroll, Scroll-Based Velocity

    Makes pages longer and slower. The old homepage was already 16,000px on desktop and about 39 screens on mobile.

    Instead: about 7 short sections in normal document flow.
  • Floating layers: Floating Navbar, Dock, floating WhatsApp bubble, Sticky Banner

    On the old mobile site a floating button, a bottom bar and the hero CTAs overlapped. Each extra floating layer covers content.

    Instead: one sticky header, plus one mobile bottom bar with 2 actions.
  • Cursor effects: Following Pointer, Smooth Cursor, Pointer, Lens, Pointer Highlight

    Takes over the cursor, does nothing on touch, and adds work on every pointer move.

    Instead: nothing. Let the content speak.
  • Count-up stats: Number Ticker

    The "big animated number" is a template cliché, and our numbers must be provable ("since 2016", "11 countries").

    Instead: plain numbers in the trust strip.
  • Modal content: Expandable Card, Animated Modal, Link Preview

    The Practice Engine had 223 modals and nothing could be linked to. Tutor profiles and questions need URLs for sharing and SEO.

    Instead: a real page per tutor and per question. Dialogs only for confirmations.
  • Novelty extras: Multi-step Loader, Confetti, Cool Mode, Placeholders and Vanish Input, Lamp, Canvas Reveal Effect, 3D Marquee

    Fun once and noise after that. Most are client-heavy, and some (Lamp, Canvas Reveal) are full-section visual effects.

    Instead: honest Skeleton/Spinner loading states and a calm success message.
  • Emoji or mixed icon sets

    Emoji subject icons and mixed Tabler/Lucide icons make the pages look like different products.

    Instead: Lucide only. Swap the Tabler imports in Aceternity code when we add it.

Dependencies and licences

  • shadcn/ui is MIT. The code is copied into the repo. Latest CLI checked: shadcn@4.21.4. Its dependencies come per component: radix-ui, class-variance-authority, lucide-react, plus recharts (Chart), sonner + next-themes, embla-carousel-react (Carousel), react-day-picker + date-fns (Calendar), input-otp, vaul (Drawer), @shadcn/react (Message Scroller, Questionnaire) and @base-ui/react (Combobox).
  • Aceternity UI: free components are copy-paste or installed through the shadcn CLI. @aceternity is listed in shadcn's official registry directory (https://ui.aceternity.com/registry/{name}.json). Typical dependencies are motion, clsx, tailwind-merge and sometimes @tabler/icons-react. Pro (blocks and templates) is paid and allows unlimited end products, but you can't resell the components or templates themselves. Every pick above is a free component, so no purchase is needed. We couldn't read the licence text for the free tier (site blocked). Confirm before launch.
  • Magic UI is MIT (license file checked on GitHub) and also listed in the shadcn directory as @magicui. Marquee has no dependencies. Blur Fade and Number Ticker need motion.
  • motion (v14 latest) is the only animation library. Add it once with the first accent component, never on its own.
  • KaTeX is MIT. The fonts are served from our own bundle via katex/dist/katex.min.css.

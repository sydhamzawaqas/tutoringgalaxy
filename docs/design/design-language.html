The Exam Paper: one design language for everything we build

Every page of Tutoring Galaxy, from the homepage to the AI practice app to the parent report, is designed like a well-made exam paper that a great tutor has just marked. It's calm, structured and precise, with one encouraging human touch. This page shows the system in use. The rules live in DESIGN.md.

This right-hand column is the system's one bold idea: a margin, like on an exam paper, for marks, times, prices and tutor notes.

Why an exam paper

Our families live inside Cambridge, Edexcel and IB papers. Parents recognise them instantly, and students trust them. So instead of space imagery or generic startup gradients, the brand borrows the most familiar, most trusted objects in education.

Borrow from the exam room

  • The question paper's structure: numbered questions, marks in the margin
  • Answer lines, ruled and quiet
  • The examiner's red-pen tick and short margin note
  • The teacher's gold star, given only when earned
  • Textbook typography: a serif for headings, a clear sans for reading

Leave behind from the old site

  • Purple and blue gradients, glass cards, glowing planets
  • A different card style in every section
  • 14 differently worded buttons and three WhatsApp bubbles
  • Emoji subject icons and cartoon avatars
  • Cream "AI-default" backgrounds. Exam paper is white

[Galaxy] lives in the name and the gold star, not in space pictures. That keeps the brand serious enough for parents paying for A Level results.

These are the only decorative devices. Each one carries meaning, so a student or parent learns it once and reads it everywhere.

A motif only appears where it means something. Gold stars can't be used as bullet points, and red can't be used for a "Sale" badge.

How we keep one design sense across the whole project

Consistency isn't a mood board. It's a chain where each step only uses what the previous step defines, and a machine checks it.

This is the main fix for the audit's top problem: three products, three looks, 116 hardcoded colours.

Rules

DESIGN.md defines colours, type, spacing, motifs and voice. Changes start here.

Tokens

The rules become CSS variables in globals.css (Tailwind v4 @theme), for light and dark.

Components

shadcn/ui components themed once in components/ui: buttons, cards, badges, forms.

Sections and templates

Hero, steps, tutor grid, pricing and FAQ are reusable sections; pages only arrange them.

Style guide

A private /styleguide page renders every token and component live.

Checks

CI fails on raw hex or arbitrary values, runs a11y lint and takes screenshots at 390 and 1440px.

Every UI change must

  • use tokens and existing components only
  • have one primary action per view
  • use sentence case and real, provable content
  • show visible focus and work at 390px
  • respect reduced motion

Never

  • add a new colour, radius or font size inside a page
  • add a third card style
  • use gold or red as decoration
  • add an animation that isn't a response to an action
  • invent tutors, reviews or statistics
